# SakuraMedia UI 实现基线

本文只记录当前代码中跨页面成立的 UI 规则。具体页面、路由、组件参数和接口行为以源码与测试为准；本文不记录规划、迁移过程或逐页字段清单。

## 产品形态

SakuraMedia 是桌面优先的媒体管理工作台。桌面端使用工作台壳层承载主要导航和系统页面；移动端使用独立的移动壳层，已经覆盖概览、影片、女优、榜单、PornBox、搜索、图搜、详情、播放器和部分设置/系统页面；Web 主要复用桌面页面并降级桌面专属能力。

平台是否真正接入某个页面，以 `lib/routes/` 的路由定义和 `lib/features/` 的页面实现为准，不根据产品规划推断支持范围。

## 视觉基线

- 整体采用浅色、克制的媒体工作台风格；桌面内容以卡片和分组承载，移动端优先保证连续滚动和触控命中区。
- 品牌强调色用于主操作、选中态和少量重点信息；状态色只表达成功、警告、错误和进行中。
- 桌面和移动可以使用不同的背景、导航和容器，但共享同一套语义 token。
- 图片、播放器和详情头图可以使用深色遮罩；普通管理页面不使用无意义的高对比装饰。

颜色、排版、间距、圆角、阴影和结构尺寸统一来自 `lib/theme.dart`。业务页面不要写裸颜色、裸字号、裸间距或裸圆角。

## 应用壳层

桌面页面优先复用：

- `AppDesktopShell`：页面整体布局、滚动区域和桌面反馈；
- `AppSidebar`：主导航和分组；
- `AppTopBar`：页面标题、搜索、筛选和操作；
- `AppPageFrame` / `AppContentCard`：页面内容宽度、内边距和卡片容器。

移动页面优先复用 `AppMobileShell` 或 `AppMobileSubpageShell`。移动底部导航只承载一级入口，详情、筛选、编辑和播放器使用子页、抽屉或底部操作层。

实现位置：`lib/widgets/shell/` 和 `lib/widgets/base/layout/`。

## 常见页面结构

### 列表页

列表页通常由页面标题/筛选操作、结果信息、响应式网格或列表、分页加载和刷新组成。优先组合：

- `AppListHeader`：标题、筛选入口、总数和操作槽；
- `AppAdaptiveCardGrid`：卡片列数和四态内容区；
- `AppPagedLoadMoreFooter`：分页加载、失败重试和完成状态；
- `AppPullToRefresh` / `AppAdaptiveRefreshScrollView`：平台自适应刷新。

桌面筛选使用页面已有的 popover 或浮层；移动筛选使用底部抽屉。筛选条件由 feature Provider 管理，页面不要维护另一份远端列表状态。

### 详情页

详情页通常由摘要/封面、信息分节、媒体和动作区域组成。桌面与移动优先共享内容 widget，仅在壳层、弹层形态、触控行为和页面边距上做平台差异。

### 设置页

桌面设置使用侧栏或分组 section；移动设置使用独立子页、列表卡片和编辑抽屉。表单字段、保存状态、删除确认和连通性测试应由当前配置域的 Provider 与共享表单组件负责。

### 播放与媒体预览

视频播放使用 `ThemedVideoPlayer` 或业务播放器 surface；图片预览使用 `MaskedImage`、全屏 host 或媒体预览 dialog。不要在业务页重复实现图片 URL、保存图片、全屏缩放和播放器控制条。

## 状态与反馈

- 首次加载使用骨架或占位块；请求失败使用明确的错误态和重试入口。
- 空结果使用 `AppEmptyState`，不要把普通空态和请求失败同时显示。
- 分页失败时保留已加载内容，并在列表底部提供重试。
- 筛选请求进行中可以保留旧结果；失败时显示行内反馈，不清空用户刚刚选择的条件。
- 删除、覆盖、离开未保存表单等不可逆或有损操作先确认。
- 轻量操作使用 toast；长任务使用任务/活动页面提供进度和结果。

## 组件与 token 入口

新增页面前先查 [`docs/widgets/`](widgets/README.md)；新增视觉语义前先查 `lib/theme/`。共享组件索引只记录当前实际存在的组件和路径，组件完整签名以源码为准。

新增共享组件或 token 后，同步更新对应分册和测试。不要把单个页面的临时实现写成全局规范。
